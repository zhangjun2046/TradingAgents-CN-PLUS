| 项目 | 内容 |

| 问题编号 | HK-NEWS-ZFILL-001 |
| 文档日期 | 2026-08-23 |
| 严重级别 | 高（可产生持久性数据污染，且报告结论完全错误） |
| 影响范围 | 全部 4~5 位港股的新闻分析链路、MongoDB 新闻缓存、历史分析报告 |

## 一、问题现象

服务器环境 `http://118.144.76.8:3000/reports/view/6a8283b7136d3161728a7561`（生成于 2026-08-17）中，
小米集团-W（01810.HK）的新闻分析报告所引用的新闻主体并非小米集团，而是
**基金代码 001810「中欧潜力价值灵活配置混合A」** 的季度业绩公告。

报告本身已在正文中提示"新闻数据匹配异常"，说明 LLM 察觉到了矛盾，但仍基于错误数据完成了分析。

同日另一次 `00180`（开达集团）的分析也出现类似问题，新闻为"低价股一览""创业板股东户数降幅排行榜"
等 A 股泛市场稿件，与目标公司无关。

## 二、根因分析

### 2.1 直接原因：A 股专用补零逻辑被用于港股

`AKShareProvider` 在获取新闻时无条件把代码补齐到 6 位，未区分市场：

```python
# tradingagents/dataflows/providers/china/akshare.py:1133-1143
# 标准化股票代码
symbol_6 = symbol.zfill(6)
...
news_df = ak.stock_news_em(symbol=symbol_6)
```

数学关系：

```text
"01810".zfill(6) == "001810"   # 港股小米 → 基金代码
"00180".zfill(6) == "000180"   # 港股开达 → A 股代码
"06030".zfill(6) == "006030"
```

相同逻辑存在于三处，必须同时修复：

| 文件 | 行号 | 方法 |
| --- | --- | --- |
| `tradingagents/dataflows/providers/china/akshare.py` | 187 | `_get_stock_news_direct`（Docker 直连） |
| `tradingagents/dataflows/providers/china/akshare.py` | 1134 | `get_stock_news_sync`（同步） |
| `tradingagents/dataflows/providers/china/akshare.py` | 1207 | `get_stock_news`（异步） |

### 2.2 关键放大因素：东方财富接口是「关键词全文搜索」

这是本次分析中最重要的发现，**它决定了"只去掉 zfill"不足以修复问题**。

```python
# tradingagents/dataflows/providers/china/akshare.py:186-193
# 标准化股票代码
symbol_6 = symbol.zfill(6)

# 构建请求参数
url = "https://search-api-web.eastmoney.com/search/jsonp"
param = {
    "uid": "",
    "keyword": symbol_6,
    ...
}
```

`ak.stock_news_em` 内部走的是同一个 `search-api-web.eastmoney.com` 搜索端点。

因此：

- 传 `001810` → 命中正文含"001810"字符串的**基金**文章（本次故障现象）；
- 传 `01810` → 只能命中正文恰好出现"01810"的文章，**不保证是小米，也可能返回空**；
- 传 `00180` → 命中含"00180"片段的 A 股统计类稿件（同日 00180 故障现象）。

**结论**：代码格式只是问题的一半。港股必须改为
**公司名 + 代码多关键词检索 + 强制相关性校验**，否则修好补零后仍会拿到无关新闻。

### 2.3 二次误判：补零后被识别为 A 股

`001810` 一旦生成，两套市场识别逻辑都会把它判为 A 股，导致错误在下游继续扩大：

```python
# tradingagents/utils/stock_utils.py:42-54
if re.match(r'^\d{6}$', ticker):
    return StockMarket.CHINA_A
```

```python
# tradingagents/tools/unified_news_tool.py:72-73
if re.match(r'^(00|30|60|68)\d{4}$', stock_code):
    return "A股"
```

并且 `_identify_stock_type` 在无法判定时**默认返回 A 股**（`unified_news_tool.py:89-91`），
进一步放大了误路由概率。

### 2.4 缓存污染：抓取码与落库码不一致

抓取用 `symbol_6`（`001810`），落库却写原始 `symbol`（`01810`）：

```python
# tradingagents/dataflows/providers/china/akshare.py:1288-1289
news_item = {
    "symbol": symbol,      # 落库写原始码 01810
    ...
}
```

结果：**基金新闻以港股代码存入数据库**。此后即使主路径修复，统一新闻工具仍会优先命中脏缓存：

```python
# tradingagents/tools/unified_news_tool.py:404-410（优先级 0：数据库）
db_news = self._get_news_from_database(stock_code, max_news)
if db_news:
    return self._format_news_result(db_news, "数据库缓存", model_info)
```

### 2.5 后台同步不区分市场，持续制造脏数据

```python
# app/worker/news_data_sync_service.py:166-169
# 批量保存
saved_count = await news_service.save_news_data(
    unique_news, "multi_source", "CN"
)
```

`sync_market_news`（同文件 493 行）同样固定 `"CN"`。且 `_sync_akshare_news`（242 行）直接调用
带补零逻辑的 Provider。**这是风险最高的一层**：用户不发起分析，脏数据也会不断累积。

### 2.6 已修复但覆盖不全的部分

港股专用同步分支已经绕开补零，并有回归测试：

```python
# tradingagents/tools/unified_news_tool.py:303-325
clean_code = stock_code.replace('.HK', '').replace('.hk', '').strip()
...
news_df = ak.stock_news_em(symbol=clean_code)
```

测试见 `tests/test_hk_news_unified.py:90-112`。

但该修复**只覆盖了统一新闻工具的港股主路径**，以下路径仍未修复：

- `AKShareProvider` 三个新闻方法；
- 实时中文新闻源 `tradingagents/dataflows/news/realtime_news.py:303-387`（对 A 股和港股均调用带补零的 Provider）；
- 同文件 860-902 的港股回退分支，判定条件是 `'.HK' in ticker`，无后缀的 `01810` 走不进来；
- 后台同步服务 `app/worker/news_data_sync_service.py`。

### 2.7 本地与远程状态差异

本地 2026-08-23 的 `results/01810/2026-08-23/reports/news_report.md` 内容正确（小米回购、汽车业务），
全仓库检索未出现 `001810`；首次代码变换是 `stock_validator` 产生的 `1810.HK`，而非 `001810`。

因此远程 8 月 17 日的错误报告最可能来自：

1. 服务器运行的是修复前版本（Worker / 容器未重建）；或
2. 走了上述任一未修复的 fallback / 后台同步路径；或
3. 命中了此前已污染的 MongoDB 缓存。

最终确认需在服务器查询：

```javascript
db.analysis_reports.findOne({ _id: ObjectId("6a8283b7136d3161728a7561") })
```

并核对 `stock_symbol`、`market_type`、`created_at`、`task_id` 及当时的数据源调用日志。

## 四、方案前提修正（对初始方案的重要修改）

初始方案方向正确，但以下三条前提站不住，需先修正，否则改完仍会出错。

### 修正 1：成功标准不能只看"参数不是 001810"

如 2.2 所述，东方财富是关键词搜索。正确的成功标准是
**"返回的新闻主体确实是目标公司"**，因此相关性校验必须与代码修复同级（P0），而不是可选优化。

### 修正 2：不能用单一函数把港股统一成 5 位

各数据源期望格式本就不同：

| 数据源 | 期望格式（01810 为例） |
| --- | --- |
| Yahoo Finance | `1810.HK`（去前导零） |
| AKShare 新浪系 | `01810` |
| Tushare 港股 | `01810.HK` |
| 东方财富搜索 | 关键词（公司名优于代码） |

正确架构是**双层**：

- **内部规范形态**：`market="HK"` + `symbol="01810"`，仅用于状态传递、数据库主键、日志；
- **Provider 适配层**：每个数据源各有一个出参格式化函数。

现有代码已隐含这种分层（如 `tradingagents/dataflows/providers/hk/improved_hk.py:151-166`），只是缺少集中管理。

### 修正 3：`stock_validator` 的 `1810.HK` 不是确定缺陷，改动有回归风险

```python
# tradingagents/utils/stock_validator.py:949-956
# 标准化港股代码格式
if not stock_code.upper().endswith('.HK'):
    # 移除前导0，然后补齐到4位
    clean_code = stock_code.lstrip('0') or '0'
    formatted_code = f"{clean_code.zfill(4)}.HK"
else:
    formatted_code = stock_code.upper()
```

日志证据显示该路径**是成功的**（`1810.HK` 正常返回"小米集团－Ｗ"），因为下游 Yahoo / 新浪接受去前导零形式。

真正的缺陷是"有 `.HK` 与无 `.HK` 两个分支输出不一致"。
这属于一致性问题，应降为 **P1**，且改动前必须逐一验证下游消费者
（`get_hk_stock_info_unified`、`get_hk_stock_data_unified`、`providers/hk/hk_stock.py:234` 的 Yahoo 分支），
否则会把一条本来能跑通的链路改坏。

## 五、初始方案遗漏的两个高危点

### 遗漏 1：唯一索引不迁移，加 `market` 会直接报错

当前唯一索引与 upsert 过滤条件都只用 `(url, title, publish_time)`：

```python
# app/services/news_data_service.py:96-101
await collection.create_index([
    ("url", 1),
    ("title", 1),
    ("publish_time", 1)
], unique=True, name="url_title_time_unique", background=True)
```

```python
# app/services/news_data_service.py:196-209
filter_query = {
    "url": standardized_news["url"],
    "title": standardized_news["title"],
    "publish_time": standardized_news["publish_time"]
}

operations.append(
    ReplaceOne(filter_query, standardized_news, upsert=True)
)
```

**若只把 `market` / `symbol` 加入 `filter_query` 而不动索引**，同一篇文章在两个 symbol 下 upsert 会命中
旧唯一索引，抛出 `E11000 DuplicateKeyError`，整个同步任务失败。

必须成对操作，且在停同步 + 备份之后执行：

1. 新建唯一索引 `(market, symbol, url, publish_time)`；
2. 灰度验证；
3. 删除旧索引 `url_title_time_unique`。

**替代方案（更推荐）**：保持"一篇文章一个文档"，用已存在的 `symbols` 数组字段
（索引见 `news_data_service.py:107`）+ `$addToSet` 表达多股票关联，并新增 `markets` 字段。
既避免跨股票重复文档，也规避唯一索引迁移风险。

### 遗漏 2：清理脏数据不能直接删除文档

由于唯一键不含 symbol，一篇文章在库中只有一份。若它被错误关联到 `01810`，
同一份文档**可能同时是其他股票的合法新闻**，直接 `delete_many` 会误删有效数据。

安全顺序：

1. 先解除错误关联（`$unset symbol` 或从 `symbols` 中 `$pull`）；
2. 仅当文档不再有任何合法关联时才删除；
3. **不要**把 `001810` 批量重写为 `01810`——`001810` 是真实存在的基金代码，其内容主体确实是基金。

## 六、完整修复方案

### 6.1 统一代码模型

内部统一使用三元组，禁止靠长度猜市场：

```python
market = "HK"
symbol = "01810"
full_symbol = "01810.HK"
```

规则：

- A 股：6 位，如 `000001`
- 港股：统一 5 位，如 `1810` / `01810` / `01810.HK` 一律归一为 `01810`
- 美股：大写字母，如 `AAPL`
- `market_type` 必须全链路传递，**不得依据 `001810` 反推市场**

```python
def normalize_stock_symbol(symbol: str, market: str) -> str:
    """内部规范形态：仅用于状态传递、DB 主键与日志。"""
    value = symbol.strip().upper()

    if market == "HK":
        value = value.removesuffix(".HK")
        if not value.isdigit() or len(value) > 5:
            raise ValueError(f"无效港股代码: {symbol}")
        return value.zfill(5)

    if market == "CN":
        value = value.removesuffix(".SH").removesuffix(".SZ")
        if not value.isdigit() or len(value) > 6:
            raise ValueError(f"无效A股代码: {symbol}")
        return value.zfill(6)

    if market == "US":
        return value

    raise ValueError(f"未知市场: {market}")
```

> `removesuffix` 需要 Python 3.9+。项目 `pyproject.toml` 声明 `requires-python = ">=3.10"`，可直接使用。

Provider 出参格式化独立一层：

```python
def to_provider_symbol(symbol: str, market: str, provider: str) -> str:
    """把内部规范形态转换为具体数据源需要的格式。"""
    ...
```

**核心不变量**：只有 `market == "CN"` 才允许 `zfill(6)`。

### 6.2 Provider 层市场感知（P0）

修改 `tradingagents/dataflows/providers/china/akshare.py` 的三个新闻方法（187 / 1134 / 1207），
为其增加显式 `market` 参数：

```python
def normalize_news_symbol(symbol: str, market: str) -> str:
    if market == "HK":
        return normalize_stock_symbol(symbol, "HK")
    if market == "CN":
        return normalize_stock_symbol(symbol, "CN")
    return symbol.strip().upper()
```

同时加入 fail-fast 断言（不只是打日志）：

```python
assert not (market == "HK" and len(query_symbol) == 6 and query_symbol.isdigit()), \
    f"港股查询码非法补零: {symbol} -> {query_symbol}"
```

**注意**：同步、异步、Docker 直连三个实现必须同时修改，只改一处会留下隐蔽 fallback。

### 6.3 港股新闻检索改造（P0）

由于东方财富是关键词搜索，港股检索改为多关键词 + 相关性闸门：

1. 优先使用公司名（如"小米集团"、"小米"、"Xiaomi"）作为检索词；
2. 辅以代码变体（`01810`、`1810.HK`、`01810.HK`）；
3. 合并去重后进入相关性闸门。

**建议补充数据源**：东方财富对港股覆盖差是结构性问题。

- FinnHub `company-news` 支持 `1810.HK` 形式，聚合器中已接入
  （`tradingagents/dataflows/news/realtime_news.py:147-195`），仅需让港股能走到该分支；
- Tushare 港股新闻可按 `01810.HK` 获取。

两者都比"拿 5 位数字搜中文全文"可靠得多。

### 6.4 实时中文新闻 fallback（P0）

修改 `tradingagents/dataflows/news/realtime_news.py`：

- `_get_chinese_finance_news`（303-387 行）：港股不得复用 A 股带补零的 Provider 路径；
- 港股回退分支（860-902 行）：判定条件由 `'.HK' in ticker` 改为
  `StockUtils.is_hk_stock(ticker)`，使无后缀的 `01810` 也能正确进入；
- 调用新闻 Provider 时显式传入 `market="HK"`。

目标流程：

```text
01810 / 01810.HK
→ normalize_stock_symbol(..., "HK")
→ 01810
→ 港股专用检索（公司名 + 代码变体）
→ 相关性闸门
```

### 6.5 后台同步按市场路由（P0）

修改 `app/worker/news_data_sync_service.py`：

```python
market = identify_market(symbol, requested_market)
normalized_symbol = normalize_stock_symbol(symbol, market)

if market == "HK":
```

`sync_stock_news`（167-169 行）与 `sync_market_news`（493 行）的硬编码 `"CN"` 都要改为真实市场。

### 6.6 统一新闻工具改造（P0/P1）

修改 `tradingagents/tools/unified_news_tool.py`：

1. `_identify_stock_type`（67-91 行）优先使用上游传入的 `market`，仅在缺失时才做推断；
2. 未知市场**返回明确错误**，不再默认走 A 股（删除 89-91 行的默认分支）；
3. 所有 fallback 分支透传 `market`；
4. 数据库查询加市场条件（见 6.7）；
5. 相关性闸门置于 `_format_news_result` 之前。

建议接口签名：

```python
get_stock_news_unified(
    stock_code="01810",
    market="HK",
    company_name="小米集团-W",
    max_news=10,
)
```

### 6.7 数据库市场隔离（P0）

当前查询仅按 symbol，缺少市场维度：

```python
# tradingagents/tools/unified_news_tool.py:127-134
query_list = [
    {'symbol': clean_code, 'publish_time': {'$gte': thirty_days_ago}},
    {'symbol': stock_code, 'publish_time': {'$gte': thirty_days_ago}},
    {'symbols': clean_code, 'publish_time': {'$gte': thirty_days_ago}},
    {'symbol': clean_code},
    {'symbols': clean_code},
]
```

改为：

```python
{
    "market": "HK",
    "symbol": "01810",
    "publish_time": {"$gte": start_time}
}
```

新增复合索引：

```python
[("market", 1), ("symbol", 1), ("publish_time", -1)]
```

唯一约束改造二选一：

- **方案 A（重建唯一索引）**：`(market, symbol, url, publish_time)`，需按遗漏 1 的三步迁移；
- **方案 B（推荐，风险更低）**：保持文档唯一性为 `(url, title, publish_time)`，
  用 `symbols` / `markets` 数组 + `$addToSet` 表达关联。

### 6.8 新闻相关性闸门（P0）

复用已有但未接入生产的过滤器：

- `tradingagents/utils/enhanced_news_filter.py`
- `tradingagents/utils/news_filter_integration.py`

目前仅在 `examples/demo_news_filtering.py`、`tests/test_news_filtering.py` 中使用。

校验维度：

- 公司名称：小米集团、小米、Xiaomi
- 代码变体：01810、1810.HK、01810.HK
- 市场：HK
- 排除冲突主体：基金、其他公司、A 股代码列表
- 相关性打分，低于阈值剔除

```python
def is_relevant_news(news, symbol, company_aliases):
    text = f"{news.title} {news.content}".lower()

    symbol_matched = any(code.lower() in text for code in symbol_aliases(symbol))
    company_matched = any(name.lower() in text for name in company_aliases)

    return symbol_matched or company_matched
```

**若全部新闻均不相关，必须返回"未获取到可靠新闻"并终止报告生成**，
不能让 LLM 基于错误数据继续分析。

### 6.9 报告名称查询（P1）

```python
# app/routers/reports.py:40-41
db = get_mongo_db_sync()
code6 = str(stock_code).zfill(6)
```

同样会把 `01810` 变成 `001810`，可能导致报告列表股票名称错配。改为按 `market_type` 处理：

```python
normalized_code = normalize_stock_symbol(stock_code, market_type)
```

名称缓存键（`reports.py:22, 32, 76, 80`）需加市场前缀：

```text
HK:01810
CN:001810
```

## 八、脏数据清理

### 8.1 前置动作

1. **暂停后台新闻同步任务**（否则边清边脏）；
2. 备份 `stock_news` 与报告集合。

### 8.2 识别可疑记录

```javascript
// 1) 港股代码但市场标记为 CN
db.stock_news.find({ symbol: "01810", market: "CN" })

// 2) 基金代码直接入库

  symbol: "01810",
```

### 8.3 清理原则

- **先解关联、后删文档**：`$unset symbol` 或 `$pull` 出 `symbols`，确认无合法关联后再删；
- **不要**把 `001810` 批量改写为 `01810`；
- 清理受污染的本地缓存（`cache/hk/hk_stock_cache.json` 等）；
- 错误报告标记为无效或删除；
- 用修复后代码重新同步并重新生成报告。

### 8.4 重点核查远程报告

```javascript
db.analysis_reports.findOne({ _id: ObjectId("6a8283b7136d3161728a7561") })
```

核对字段：`stock_symbol`、`market_type`、`news_report`、`created_at`、`task_id`，
并对照当时的数据源调用日志。

## 十三、一句话结论

新闻分析师本身没有给代码补零，是 `AKShareProvider` 把所有代码按 A 股规则补成 6 位，
使 `01810` 变成基金代码 `001810`；更深层的问题是东方财富接口本质为关键词全文搜索，
**因此修复必须同时包含"Provider 市场感知 + 港股按公司名检索 + 相关性闸门 + 数据库市场隔离 + 脏数据清理"**，
只重新部署港股专用分支不足以解决问题。
