# HunterAgent 移动端与合规技术决策纪要

> 整理日期：2026-10-17  
> 产品名：**HunterAgent**  
> 主体方向：北京万商云猫智汇园区管理服务有限公司  
> 本文归纳自项目可行性讨论，供后续排期与决策使用。

---

## 1. 结论总览

| 议题 | 结论 |
|------|------|
| 微信小程序承载完整股票分析 | **无金融资质则基本不可过审**；免责声明无法绕过类目资质 |
| 手机端主技术路线 | **Web / PWA**（不走小程序） |
| 公众号挂接 | 认证服务号/订阅号菜单可跳转 **HTTPS 备案域名**；与小程序审核不同 |
| 裸 IP（如 `http://IP:3000`）挂菜单 | 技术上偶发可用，**不适合正式入口** |
| 专有许可（`app/`、`frontend/`） | 路径 A：基于 Apache 核心自研壳；短期可先 H5 验证，**勿对外收费** |
| 商业模式（卖算力/订阅） | 逻辑可借鉴；须先有授权或完成路径 A |

## 2. 微信小程序 vs Web/PWA

### 2.1 为何不做完整分析小程序

微信按**实际功能**归类，不按「学习研究」自我定位：

| 能力 | 常见类目 | 资质门槛（概要） |
|------|----------|------------------|
| 个股分析 / 咨询倾向 | 证券/期货投资咨询 | 《经营证券期货业务许可证》等 |
| A 股行情、K 线、走势分析 | 股票信息服务平台 | ICP/增值电信 + 上交所/深交所信息经营许可等 |
| 港股/美股行情分析 | 股票信息服务平台（港股/美股） | 仍属金融业，主体要求更严 |

无上述资质时：

- 选「教育/工具」类目却做真股分析 → 类目不符，易拒审；
- 提审阉割、上线后再开金融功能 → 平台禁止的规避行为。

**无资质可行做法**：小程序仅做 AI/多智能体**学习内容 + 导流**（跳转浏览器打开 Web）；真分析留在 Web/PWA。

### 2.2 选定路线：Web / PWA +（可选）公众号

| 渠道 | 无金融资质下可行性 | 说明 |
|------|-------------------|------|
| 响应式 Web / H5 | 高 | 无小程序类目资质墙 |
| PWA | 高 | 本仓库前端已有 `vite-plugin-pwa` 基础 |
| 微信公众号菜单跳 H5 | 高（需认证号） | 引流层，不审整站代码；仍受外链/金融营销规范约束 |
| 原生 App / 其他小程序 | 中低 | 应用商店/类目同样可能卡金融资质 |

**说明**：不做小程序 ≠ 只能「Web+公众号」；但对「无资质 + 保留真股分析」而言，这是性价比最高的大众方案。

## 3. 公众号挂接要点

### 3.1 账号与菜单

- 建议：**企业认证服务号**（认证订阅号也可挂外链，能力较弱）。
- 自定义菜单最多 **3 个一级 × 每级 5 个二级**。
- 类型选「跳转网页」，URL 填：`https://已备案域名/路径`。
- **菜单跳转一般不要求**额外「域名挂接产品」；仅当需要微信网页授权 / JSSDK 时，再配置授权域名、JS 安全域名（须备案域名，不支持 IP、不支持端口）。

### 3.2 域名与备案

| 项 | 说明 |
|----|------|
| ICP 备案 | 大陆主机建站常规要求；**一般不依赖证券/投顾牌照** |
| 触发金融前置 | 单位名称/经营范围/**网站名称**含证券、投顾等敏感词时，管局可能要求金融审批文件 |
| 备案填报建议 | 按技术/教育/软件服务表述，避免按「证券资讯平台」申报 |
| HTTPS | 正式入口必须 HTTPS |
| 裸 IP + HTTP + 非 443 端口 | 仅适合内测；正式挂服务号不推荐 |

### 3.3 公众号命名（已讨论方案）

| 项 | 建议 |
|----|------|
| ❌ 不宜使用 | `北京万商云猫智汇园区管理服务有限公司-AI/多智能体学习与研究助手`（超长；`/` 通常不在允许特殊符号内；不必写全公司名） |
| ✅ 产品名 | **HunterAgent** |
| ✅ 公众号昵称示例 | `HunterAgent学习助手` / `万商云猫HunterAgent` |
| 注意 | 勿使用与官方「TradingAgents-CN」易混淆名称；主体信息在认证资料中体现 |

### 3.4 公众号 vs 小程序审核差异

- 公众号菜单挂 H5：**通常无**「上传金融许可证才能保存菜单」的前置关。
- 仍受《微信外部链接内容管理规范》等约束：无牌照有偿投顾、违规荐股、夸大收益等可被治理。
- 定位「AI 学习」适合简介与部分菜单；落地页若是完整股票分析，**不能**单靠定位规避内容治理。

## 4. 专有许可与路径 A

### 4.1 许可结构（本仓库）

| 组件 | 许可 | 含义 |
|------|------|------|
| `tradingagents/`、`cli/`、`docs/` 等 | Apache 2.0 | 可使用、修改、分发（遵守 Apache） |
| `app/`、`frontend/`（上游说明中或含 `core/`） | **专有** | 禁止再分发、禁止未授权商用、禁止修改衍生；仅个人评估/非商业教育等 |

联系授权（上游声明）：`hsliup@163.com`  
官方仓库：https://github.com/hsliuping/TradingAgents-CN  

「上游 TradingAgents 开源」≠「CN 的 Web 壳也开源」。CN 作者在开源引擎上自研了 `app`/`frontend` 并单独锁定，合法。

### 4.2 路径 A（长期合规终局）

**定义**：只基于 Apache 部分自建 **HunterAgent** Web：

1. 对接 `tradingagents` 等开源核心（如 `TradingAgentsGraph.propagate`）；
2. **自研** API + 移动端 H5（**不复制** `app/`、`frontend/`）；
3. 品牌用 HunterAgent；关于页致谢 TradingAgents（及合规范围内的来源说明）。

**技术难点**：

- 分析引擎调用本身不难；难在任务队列、进度、报告、登录等产品壳；
- `tradingagents/` 部分文件存在对 `app.*` 的反向依赖，干净部署前需解耦。

**深度 AI 并行（参考「服务器无人值守流水线」做法）**：

- 指挥层：人 + 本地 AI 写总控规则与任务书、拍板；
- 开发机：多条流水线并行（core 解耦 / API / H5）；
- 验证层：真机安装 + Playwright；真实分析用便宜模型做冒烟；
- 合规隔离：新建仓库只纳入 Apache 目录；CI 禁止 `from app`；禁止 AI 读取专有源码树。

粗估（AI 流水线深度使用时）：MVP（登录+单股分析+报告+H5）约数天量级；全量用户功能对等更长。串行手搓周期显著更长，不作为主估算。

### 4.3 与 tradingagents-ai.com 的关系（公开信息）

- 上游 README **公开点名** `tradingagents-ai.com`：称未授权使用专有代码、未向任何组织发放商业授权。
- 公开检索：**未见**针对该站的法院判决/行政处罚结果报道；对方站点检索时仍在线。
- **未见**大量针对「个人学习部署」的公开投诉名单。
- 含义：作者对「未授权商用/冒充产品」有维权意愿与公开行动先例；手段目前可见偏声明与舆论，不代表永远无诉讼。

### 4.4 「卖算力 / 卖订阅」能否借鉴

| 内容 | 结论 |
|------|------|
| SaaS、按 Token/次数计费、订阅档、部署服务费 | **商业逻辑可借鉴**（通用模式） |
| 在未授权的 CN `app`/`frontend` 上对外收费 | **不可借鉴**（与被点名类型同构） |
| 路径 A 完成或取得书面商业授权后计费 | **可以**；收费仅针对自有服务，勿冒充官方 CN |

## 5. 分阶段实施策略（已对齐的业务判断）

### 5.1 产品节奏（成本优先）

在用户规模不确定、暂不盈利的前提下：

1. **先做移动端 H5 / PWA**（验证需求，工作量相对小）；
2. **是否挂公司服务号**：可选；不挂可进一步降低微信侧暴露；
3. **路径 A**：按触发条件启动，避免过早消耗人力与 Token。

说明：先做 ①②、暂缓 ③，在「不确定有没有客户」时是合理的商业取舍；**不等于**许可风险为零。

### 5.2 风险随暴露度变化

| 形态 | 相对风险 |
|------|----------|
| 仅本机 / 内网 | 最低 |
| 公网 + 访问控制（密码/白名单） | 较低 |
| 公网开放 H5/PWA，**不挂**公司公众号 | 中等偏低（无微信投诉通道，许可问题仍在） |
| 公网 + 公司服务号引流 | 较高 |
| 公网 + 收费（算力/订阅） | 最高（接近被点名类型） |

**只做 H5/PWA、不挂公众号**：微信侧风险基本去掉；著作权侧风险降低但未消失。

### 5.3 路径 A 建议触发条件（满足任一即启动）

- 原作者联系或书面拒绝授权；
- 收到平台投诉 / 函告；
- 用户量达到自定门槛（例如注册或日活达到验证目标）；
- 准备产生任何收入或大规模推广。

### 5.4 上线前零成本建议动作

1. 邮件联系作者说明：公司主体、不收费、学习/内测用途、规模预期，请求书面许可或书面确认边界（`hsliup@163.com`）；
2. 关于页保留来源与许可说明（避免抹去署名被认定为恶意）；
3. 可选：写好路径 A 的 M0（总控规则、OpenAPI 契约、功能清单），以便触发后数天内可拉起流水线。

### 5.5 关于「学习声明」与索赔预期（非律师意见）

- 「仅供学习」**不能**自动免除专有许可限制；公司主体公网提供会弱化「个人使用」叙事。
- 公开检索未见针对普通学习者的高额索赔判例；不收费、低曝光、被通知后立即停用，**高额索赔预期偏低**，但不能称为零。
- 会放大风险的行为：去署名、收费、被通知后继续运营、冒充官方品牌。
- 《著作权法》对故意侵权有惩罚性赔偿空间；是否起诉取决于权利人策略，不能仅以「中国 AI 迭代快」否定权利存在。

## 6. 技术实现要点（H5 / PWA 阶段）

基于现有仓库能力（决策用，非实施清单）：

| 能力 | 现状 | H5/PWA 阶段建议 |
|------|------|-----------------|
| 前端 | Vue3 + Element Plus + PWA 插件 | 优先补齐移动端体验：单股分析、报告、自选 |
| 后端 | FastAPI + JWT + 任务状态轮询 | 小程序式 SSE/WS 可弱化，H5 用轮询即可 |
| 报告分享 | 已有公开 `/s/:token` | 适合手机分享阅读 |
| 管理后台 | 设置/同步/调度等 | 不必作为手机端重点 |

微信内打开多为内置浏览器 H5；**完整 PWA 安装**更依赖系统浏览器「添加到主屏幕」。
